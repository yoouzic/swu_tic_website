# SWU-TIC UI/UX 最终收口实施计划

> 基线：`71fff95e06fcfcc42d96b523f900ee1cc5e643bc`（`agent/ui-ux-third-pass-finalization`）
> 审计日期：2026-08-14
> 范围：现有 Flask / Jinja / Bootstrap 产品的最终 UI/UX 深度审计、设计系统收口、响应式修复、权限反馈与可访问性优化。保持路由、表单字段、DOM ID、fetch/API 合约、权限语义、人工复核字段和破坏性操作确认不变。

## 1. Current State

- 产品主框架已经形成稳定的 Workspace Shell：左侧导航、顶部栏、PageHeader、Metric、空状态和状态徽章均有共享实现，`/`、`/admin/statistics` 和 `/admin/review_forms` 是本轮必须复用的成熟基准。
- 当前工作树在审计开始时干净；历史报告只用于定位，本节结论来自当前 HEAD 的源码、129 项定向测试和本轮 5097 隔离运行时截图。
- 设计令牌已集中在 `app/static/css/style.css`，但后续页面仍混用 Bootstrap 栅格、内联样式、页面私有卡片和旧的语义色按钮。
- 统计首页已经采用统一页头、指标和统计导航；三个统计子页仍保留旧页头、旧操作区和不稳定的卡片/筛选布局。
- 审核队列的主从工作台在桌面端成熟；筛选区在 1440px 的窄队列栏中使用双列是合理的，但同一硬编码规则在 1024px 全宽队列中仍强制双列，导致第五个筛选项孤立。
- 审核详情功能完整，但存在“一张外层大卡片包多张内层卡片”、大号绿/红/灰动作按钮、模板内样式、非语义抽屉标题控件和移动端评分表格拥挤等收口问题。
- “预约与表单”桌面页已经使用统一页头和标签导航；表单列表仍是九列宽表，390px 下依赖约 675px 的容器横向滚动，尚未迁移为移动端信息卡。
- 权限辅助函数已经存在并被部分路由使用；多个旧路由仍直接返回“无权限/没有权限”字符串，造成反馈文案、资源对象和 HTTP/JSON 语义不一致。

## 2. Confirmed Problems

### P0 — 响应式与关键任务流

1. `review_forms.html` 的筛选列宽由 Bootstrap `col-md-*` 与全局覆盖共同决定。实测 1024×768 时队列转为全宽，但筛选仍为两列，形成四项 + 一项的孤行；这是容器状态与 viewport 断点脱节的根因。
2. `review_form.html` 的评分表格在 390×844 时虽没有 body 级横向溢出，但“评分原因 / 部门扣分 / 个人扣分 / 操作”被压缩到约 104 / 63 / 63 / 44px，多行修改时阅读和输入负担过高。
3. `my_forms.html` 的九列表单表在 390px 下宽约 1016px，父容器横向滚动约 675px；核心状态和操作不能在一个视口内完成扫描。

### P1 — 视觉层级与设计系统

1. `review_assessment_stats.html`、`submission_count_stats.html`、`department_monthly_assessment_stats.html` 没有复用统计首页 PageHeader 与统计子导航，筛选/操作按钮在 1440px 仍换成两行，卡片高度不一致。
2. 统计子页把导入/导出等普通操作渲染为绿色成功语义，削弱真正成功状态与主要动作的辨识度。
3. `review_form.html` 的外层卡片、章节卡片、审核信息强调卡叠加边框和 padding；主内容层级被“卡片套卡片”取代。
4. 审核提交、驳回和重置使用同等级 `btn-lg` 实心色块，主要动作、危险动作、次要动作的层级不足。

### P1 — 可访问性与交互

1. 参考数据抽屉头部由带 `onclick` 的 `div` 充当控件；打开按钮缺少 `aria-expanded` / `aria-controls` 状态同步。
2. 实测抽屉打开后按 Escape 不关闭，`aria-hidden` 仍为 `false`，没有焦点返回契约。
3. 动态评分行缺少移动端标签信息，表头隐藏后无法建立字段含义。

### P2 — CSS 与反馈一致性

1. 审核详情仍包含大段模板内 `<style>`，同一组件难以复用和做全局断点审计。
2. 权限拒绝反馈仍有旧字符串和自建 JSON，资源对象、动作和原因不够一致；部分 JSON 分支的 403 状态也需要回归锁定。

## 3. False Positives

- **审核队列 1440px 双列筛选不是问题。** 该区域位于约 390px 的队列栏，实测字段宽约 183px，双列比单列更紧凑；修复应针对容器变宽后的布局，而非全局改成单列。
- **所有卡片都不是问题。** 指标、空状态、结果分组和需要独立边界的摘要仍适合卡片；本轮只移除没有独立语义的审核表单嵌套卡片。
- **所有表格都不应卡片化是错误结论。** 版本历史、密集统计结果和桌面数据比较仍使用表格；只有移动端主任务所需的九列表单和评分输入改为响应式卡片/堆叠行。
- **状态为 0 不是空状态。** 数值 0 必须继续呈现为有效统计值；只有无记录集合才使用 EmptyState。
- **听课登记统计不强行并入管理员统计导航。** `registration_statistics.html` 是课程管理上下文的下钻页；它应复用 PageHeader/动作层级，但保留返回课程管理的信息架构。
- **不重做品牌与 App Shell。** 本轮不引入新配色、新字体、新 UI 框架或页面级视觉语言。

## 4. Root Causes

1. **断点按 viewport 编写，组件却按容器变化。** 审核筛选栏同时出现在桌面分栏和中屏全宽两种容器中，Bootstrap 列断点无法表达真实可用宽度。
2. **页面迁移停在“外壳统一”。** 新 Workspace Shell 已覆盖主路由，但统计子页和审核详情的内部结构仍沿用旧页面模板。
3. **共享原语缺少统计子页与复杂表单两类布局。** 现有 PageHeader/Metric 足够，但缺少统计工具栏、筛选网格、表单章节和响应式动作区的轻量约束。
4. **功能脚本先于语义与键盘契约演进。** 抽屉和评分行能工作，却没有同步 ARIA 状态、Escape 和移动端字段标签。
5. **权限辅助函数为增量引入。** 新路由采用统一反馈，旧路由仍散落硬编码，导致同类拒绝产生不同用户体验。

## 5. Implementation Phases

### Phase A — 建立 RED 合约

- 新增 `tests/test_ui_final_convergence.py`，先锁定以下失败事实：统计子页未统一、审核筛选仍依赖 `col-md-*`、审核详情存在旧动作层级/模板内样式/非语义抽屉、评分行缺少移动标签、我的表单仍是移动宽表、目标权限分支仍有硬编码。
- 运行新增测试，确认失败来自当前实现而不是环境或夹具。

### Phase B — 共享布局与统计子页

- 新增 `app/templates/partials/_statistics_nav.html`，由统计首页和三个子页共享 active 状态与权限可见性。
- 在 `style.css` 增加 token 驱动的统计筛选网格、操作区、结果区和容器感知审核筛选规则。
- 迁移 `review_assessment_stats.html`、`submission_count_stats.html`、`department_monthly_assessment_stats.html` 到 PageHeader + 统计导航 + 统一筛选/操作层级；保持 ID、handler、表单 action 和导入导出行为。
- `registration_statistics.html` 复用 PageHeader 与动作层级，但保留课程管理返回路径。

### Phase C — 审核队列与审核详情

- `review_forms.html` 用语义类替代硬编码 `col-md-*`；窄队列保持两列，中屏全宽允许三列，手机单列。
- `review_form.html` 移除无语义的外层/内层卡片套娃，改为共享 surface + section；保留所有表单字段、name、ID、权限逻辑和提交流程。
- 动作区统一为主按钮、危险按钮和次要轮廓按钮；移动端堆叠并保持触控尺寸。
- 将参考抽屉样式移入 `style.css`；用 button 取代可点击 div，同步 `aria-expanded` / `aria-hidden`，实现 Escape 关闭与焦点返回。
- 动态评分行增加字段标签并在小屏转为堆叠卡片，不改变后端评分 payload。

### Phase D — 我的表单与权限反馈

- `my_forms.html` 保持现有 PageHeader/标签外壳，给核心列表补齐移动端 `data-label` 与卡片式表格类；桌面仍为表格，版本历史仍为真实表格。
- 扩展 `permission_feedback.py` 的可选动作语义，默认输出保持兼容；把本轮确认的用户可见硬编码分支迁移到 `forbidden_json` / `flash_forbidden`，并保留 403、重定向和授权边界。

### Phase E — 验证、截图与结论

- 新测试先转 GREEN，再运行既有组件、Shell、响应式、权限、统计、审核和用户表单回归。
- 使用项目 sibling venv 运行全量 `unittest discover`。
- 在隔离 5097 运行时对 1440、1280、1024、900、768、430、390、360px 做 DOM 几何矩阵；对关键 before/after 状态保存截图并人工检查。
- 只在完成源代码、单元/静态、真实浏览器和可逆交互验证后给出完成或残余风险结论；本轮不 commit、不 push。

## 7. 退出条件

- 关键路径无新增横向滚动、遮挡、截断、失焦或不可达控件。
- 共享组件替代重复页面结构，但不引入第二套设计系统。
- 所有改动均有当前运行证据；“未覆盖”与“无法验证”必须单列，不以静态测试替代浏览器验收。
- Git 发布只包含本轮明确范围内的源代码、测试、文档与审计截图；仅推送个人私有 `origin`，部门 `upstream` 保持禁用。
