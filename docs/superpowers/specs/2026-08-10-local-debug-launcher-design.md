# 本地调试启动器设计

## 背景

当前项目通过 `app/app.py` 启动 Flask，默认数据库位于 `data/instance/lecture_forms.db`。仓库已有 `tools/init_user.py`，可以初始化数据库并创建三种角色的演示账号，但缺少适合 Windows 双击使用的启动、停止和状态管理入口。

本设计新增一个中文菜单式 CMD 启动器，让开发者无需手工配置环境变量、查找 Python 进程或重复输入账号信息，即可启动和关闭本地网页。

## 目标

- 在仓库根目录提供一个可双击的 `本地调试.cmd`。
- 默认显示中文菜单，并支持启动、关闭、重启、状态检查和打开网页。
- 使用独立调试数据库，不读取或修改默认业务数据库。
- 每次启动时准备三个固定测试账号，密码统一为 `1234564`。
- 将调试数据库中所有“管理员”和“超级管理员”账号密码重置为 `1234564`。
- 自动打开浏览器，并保留独立 Flask 日志窗口。
- 精确管理由启动器创建的进程，不按进程名批量结束 Python。
- 所有运行状态、数据库、上传文件和日志都位于 Git 忽略目录。

## 非目标

- 不改变生产部署方式、生产数据库配置或业务权限规则。
- 不自动安装 Python、虚拟环境或第三方依赖。
- 不删除调试数据库；关闭后保留调试数据。
- 不提供局域网访问，服务只监听 `127.0.0.1`。
- 不修改默认业务数据库中的现有用户密码。

## 用户界面

双击 `本地调试.cmd` 后显示：

```text
========================================
       西大听课工作台 · 本地调试
========================================

当前状态：未运行
访问地址：http://127.0.0.1:5000

[1] 启动服务
[2] 关闭服务
[3] 重启服务
[4] 查看运行状态
[5] 打开本地网页
[0] 退出

请输入操作编号：
```

菜单行为：

- `1`：准备调试数据库和账号，启动服务，等待健康检查通过后打开浏览器。
- `2`：结束 PID 文件记录的进程树，清理失效 PID 文件。
- `3`：先关闭，再执行完整启动流程。
- `4`：显示 PID、进程状态、端口状态和 HTTP 可访问状态。
- `5`：仅打开浏览器，不隐式启动服务。
- `0`：关闭菜单，不结束正在运行的服务。
- 无效输入显示提示，并返回菜单。

同时支持自动化参数：

```text
本地调试.cmd start
本地调试.cmd stop
本地调试.cmd restart
本地调试.cmd status
本地调试.cmd open
```

## 组件设计

### `本地调试.cmd`

负责用户可见入口、中文菜单、参数分发和退出码传递。它不直接拼装复杂进程命令，而是调用 PowerShell 管理器完成具体操作。

### `tools/local_debug.ps1`

负责：

- 解析 `start`、`stop`、`restart`、`status` 和 `open`。
- 计算仓库绝对路径和调试运行目录。
- 选择并验证 Python 解释器。
- 设置仅对初始化和 Flask 子进程生效的调试环境变量。
- 运行调试数据库准备脚本。
- 启动独立、可见的 Flask 日志窗口并保存其 PID。
- 轮询本地 HTTP 地址，成功后打开默认浏览器。
- 根据 PID 文件精确关闭进程树。
- 检测 PID 失效、端口冲突、依赖缺失和启动超时。

### `tools/prepare_local_debug.py`

负责调试数据准备：

- 在启动器指定的独立 SQLite 数据库中执行 `init_database()`。
- 创建或更新以下账号：

| 登录账号 | 角色 | 密码 |
| --- | --- | --- |
| `super` | 超级管理员 | `1234564` |
| `manager` | 管理员 | `1234564` |
| `user001` | 信息员 | `1234564` |

- 保留 `manager` 所需的“管理部门”和“审表_部门”测试权限。
- 将该调试数据库内其他“管理员”和“超级管理员”的密码一并重置为 `1234564`。
- 不接受或推导默认业务数据库路径；数据库路径必须由启动器显式提供。

## 调试运行目录

所有运行产物放在现有 Git 忽略目录下：

```text
data/instance/debug/
├── lecture_forms-debug.db
├── local-debug.pid
└── local-debug-state.json

data/storage/debug/
├── uploads/
└── logs/
```

关键环境变量：

```text
APP_ENV=development
FLASK_DEBUG=1
FLASK_RUN_HOST=127.0.0.1
FLASK_RUN_PORT=5000
INSTANCE_DIR=<repo>/data/instance/debug
SQLITE_DB_PATH=<repo>/data/instance/debug/lecture_forms-debug.db
UPLOAD_FOLDER=<repo>/data/storage/debug/uploads
DATABASE_URL=
```

显式清空 `DATABASE_URL`，避免调用者机器上的全局变量把调试启动器意外连接到其他数据库。

## Python 解释器选择

按以下顺序检查：

1. 当前仓库 `.venv/Scripts/python.exe`。
2. 同级 `SWU_TIC-main/.venv/Scripts/python.exe`，兼容当前工作区现状。
3. Windows `py -3` 启动器。
4. PATH 中的 `python.exe`。

选中解释器后先探测 Flask、SQLAlchemy 和 Werkzeug 是否可导入。若依赖缺失，启动失败并显示建议命令，不自动联网安装。

## 启动流程

1. 检查 PID 文件。
2. 若记录进程仍存在且 HTTP 可访问，报告“已经运行”，不重复启动。
3. 若 PID 文件失效，清理陈旧状态。
4. 检查 `127.0.0.1:5000`；若被非本启动器进程占用，停止并提示，不结束占用者。
5. 创建调试运行目录。
6. 设置隔离环境变量并执行 `prepare_local_debug.py`。
7. 数据准备成功后，在独立 CMD 窗口运行 Flask。
8. 保存日志窗口进程 PID及启动时间。
9. 最多等待约 30 秒，轮询 `http://127.0.0.1:5000/`。
10. 成功后打开默认浏览器，并在菜单中显示三个测试账号。
11. 超时则保留日志窗口供排查，并返回非零退出码。

## 关闭流程

1. 读取 PID 文件并验证记录进程是否仍存在。
2. 仅对该 PID 执行 Windows 进程树终止，覆盖 Flask 调试重载产生的子进程。
3. 再次检查进程和端口是否释放。
4. 删除 PID 和临时状态文件；保留数据库、上传文件和日志。
5. PID 已失效时只清理状态，不结束任何其他进程。

禁止使用 `taskkill /IM python.exe`、`Stop-Process -Name python` 等按名称批量结束方式。

## 错误处理

- Python 不可用：显示探测过的候选路径和安装提示。
- 依赖缺失：列出缺失导入并提示使用 `requirements.txt`。
- 端口被其他进程占用：显示端口冲突，不自动换端口或杀进程。
- 数据库初始化失败：不启动 Flask，保留错误输出。
- Flask 启动超时：保留日志窗口，状态命令显示 HTTP 不可访问。
- PID 文件损坏：视为陈旧状态并安全清理。
- 浏览器打开失败：服务继续运行，显示可手动访问的地址。

## 测试与验收

### 自动化测试

- 使用临时目录验证调试数据准备脚本，不接触默认数据库。
- 验证三个固定账号存在、角色正确且密码哈希可通过 `1234564` 校验。
- 验证额外管理员账号会被统一重置，普通信息员不会被意外重置。
- 验证 CMD 菜单、命令参数和 PowerShell 操作契约存在。
- 对 PowerShell 进行语法解析，对 Python 文件进行编译检查。

### Windows 真实验收

- `status` 在未启动时返回未运行。
- `start` 创建独立数据库、显示日志窗口并打开网页。
- 三个账号均可登录对应角色工作台。
- 重复 `start` 不产生第二个服务。
- `restart` 更换 PID 后仍可访问。
- `stop` 后端口释放，日志窗口关闭，数据库仍存在。
- 非启动器占用 5000 端口时不会被误杀。
- 仓库工作树不出现数据库、PID、日志或上传产物。

## 安全边界

`1234564` 是明确批准的本地调试密码，只允许写入独立调试数据库。启动器不应读取、复制或修改默认业务数据库，也不应监听局域网地址。菜单需要明确标识“本地调试”，避免将该启动方式误认为生产配置。
