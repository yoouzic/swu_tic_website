# 全员听课助手与角色化提交模板设计

- 日期：2026-09-28
- 状态：已确认产品方向，等待实现计划
- 适用仓库：`SWU_TIC-submit`
- 当前边界：所有登录用户可使用听课助手；第一阶段兼容现有信息员提交流程；教师/督导提交模板单独设计，不伪装成信息员表单

## 1. 设计结论

“老年教师功能”升级为面向所有人的“听课助手”。老年教师是首个验证场景，不再是产品边界。助手负责降低课程识别和基础信息填写负担；身份、权限、必填字段、审核和统计归属仍由服务端的提交模板决定。

统一产品入口使用“听课助手”或“引导填报”，不暴露“老年模式”概念。大字号、分步操作、清晰状态、大点击区域和键盘可用性作为默认基础体验，而不是年龄专属开关。

## 2. 目标与非目标

### 目标

1. 让所有允许访问的登录用户通过“日期 → 教室/教师 → 课程卡片 → 人工确认”找到课程。
2. 自动带出课程、教师、教师学院、班级、地点和节次，但始终允许修改。
3. 保留“都不是”、修改日期、修改教室、备用线索和手动补充路径。
4. 记录课程来源、候选、冲突、人工覆盖和最终确认，支持后续评估。
5. 不破坏现有信息员表单、草稿、版本、提交去重和审核流程。

### 非目标

- 不把推荐结果直接当成课堂事实或自动提交。
- 不把所有用户强制到同一套表单字段。
- 不用学号、学生签名、学生电话或空字符串伪造教师/督导字段。
- 第一阶段不加入语音、聊天式 AI、自动扩写评价或地理位置证明。
- 不把历史数据库课程记录全量并入当前权威课表。

## 3. 方案比较

### 方案 A：全员助手 + 角色化提交模板（采用）

所有用户共用课程查找和纠错体验，提交时按身份进入信息员或教师/督导模板。课程匹配逻辑只维护一份，角色规则独立维护。它能复用现有系统的课表快照、草稿和提交能力，同时不污染 `LectureForm` 的学生专用语义。

### 方案 B：按年龄做“适老模式”

实现直观，但会把可访问性误解为年龄标签，并产生重复的页面和分支。放大文字、分步确认和错误恢复本来就适合所有人，因此不采用年龄作为产品分流条件。

### 方案 C：所有人直接使用 AI 对话填表

表达灵活，但难以保证必填项、身份规则、候选来源和人工确认。保留为远期表达辅助，不作为第一阶段入口。

## 4. 领域边界

### 4.1 听课助手会话

助手会话是一次课程查找和确认过程，包含：

- 查找输入：听课日期、具体教室或教师；
- 候选卡片：课程、教师、学院、班级、地点、节次、来源和冲突标记；
- 用户动作：选择、拒绝、修改条件、切换来源、手动补充；
- 最终快照：用户确认的字段、人工覆盖字段、来源批次和模板版本。

会话可以暂存在现有 `LectureFormDraft.payload_json` 的命名空间中，但不能信任客户端快照作为提交事实。提交时服务端必须重新解析和校验候选来源。

### 4.2 课程来源

当前权威课表通过现有 `resolve_current_schedule_snapshot()` / `ScheduleSemesterSelection` 选择。助手默认只查询当前权威来源。

备用来源只能由用户在“都不是”或无结果后主动触发。备用卡片必须显示“备用课表线索／需核对”，不应静默覆盖用户原先的日期、地点或节次。节次和地点冲突采用“需确认”，不硬过滤掉候选。

### 4.3 提交模板

提交模板由身份配置决定，而不是由 UI 模式决定：

| 模板 | 第一阶段处理 | 字段/权限原则 |
|---|---|---|
| 信息员 | 接入现有 `LectureForm` | 保留现有学生签名、电话、评价和审核规则 |
| 教师/督导 | 单独设计和实现 | 不复用学生签名、学生电话和学生专用校验 |
| 管理员 | 不默认开放提交 | 仅在明确权限和业务需要时启用 |

“助手模式”只是减少寻找和输入的交互方式，不能改变谁能提交、谁能查看或记录计入什么统计。

## 5. 现有系统接入点

第一阶段应沿用而不是替换这些边界：

- `app/blueprints/user/forms.py`：现有 `/user/submit_form`、草稿接口、版本和重复提交事务；
- `app/blueprints/user/reservations.py`：现有听课与填报工作台和课程查询入口；
- `app/templates/user/lecture_form.html`：现有信息员表单及学生专用字段；
- `app/templates/user/activity_center.html` / `app/static/js/activity-center.js`：现有工作台导航、课程搜索和记录交互；
- `app/services/schedule_snapshots.py` / `app/services/review_schedule_source.py`：课表批次和权威来源选择；
- `app/services/review_schedule_matcher.py`：已有课表匹配能力，新增助手匹配应通过独立服务组合，不直接改变自动审核的冻结算法。

## 6. 组件与数据流

### 5.1 组件

1. `ListeningAssistantService`：接收查找输入，调用权威课表解析器，返回去重后的候选和来源元数据。
2. `CandidateNormalizer`：统一地点、节次、班级和多场地表达，保留原始文本；不使用未经验证的模糊同义词替换。
3. `SubmissionProfile`：根据当前用户身份决定表单字段、校验、查看范围、审核标签和统计归属。
4. `ListeningAssistantEvidence`：保存一次确认的来源批次、查找输入、候选身份、人工修改和确认时间；与 `LectureForm` 形成附加关系，不改变既有字段含义。
5. 现有草稿服务：继续使用 `/user/api/lecture_form_draft`，助手状态放入明确的 `assistant` 命名空间，提交成功时一并清理。

### 5.2 主流程

```text
登录用户
  -> 听课助手
  -> 日期
  -> 具体教室或教师
  -> 当前权威课表候选
  -> 课程卡片/都不是/修改条件
  -> 可选备用线索
  -> 人工确认地点、节次和来源
  -> 按身份进入提交模板
  -> 服务端重新校验并保存确认快照
```

### 5.3 建议接口边界

接口名称可以在实现计划中按现有蓝图命名，但必须满足以下语义：

- `GET` 候选接口：只接受日期、教室/教师和来源模式，返回候选、来源、冲突和可编辑字段；不返回超出权限的个人数据。
- 备用查询接口：必须显式携带用户触发的备用原因或会话状态，不能由空结果自动切换。
- 草稿接口：保留现有用户隔离和 JSON 白名单，新增助手状态不影响旧草稿。
- 提交接口：客户端只提交选择和覆盖意图；服务端根据当前学期权威批次重新校验，生成 `ListeningAssistantEvidence`，再进入对应提交模板。

## 7. 错误与安全处理

- 当前学期未配置、权威课表不存在、批次指针无效或数据解析不完整：显示明确状态，提供手动填写，不静默选择另一份课表。
- 候选不唯一：展示课程、教师、班级、教室和节次，禁止自动选择第一项。
- 候选与实际地点/节次冲突：保留候选并要求明确选择实际值。
- 用户点击“都不是”：排除已展示卡片，允许修改日期/教室、按教师查找、备用查询和手动补充。
- 用户切换日期或教室：清除失效候选，但保留与课程无关的评价草稿，并向用户说明哪些基础字段会变化。
- 提交时重新校验用户身份、候选来源、当前批次、表单归属和模板权限；客户端传来的学院、班级、课程号不能直接成为权威事实。
- 候选来源、手动覆盖和确认动作只保存必要的结构化证据，不记录不必要的自由文本或敏感数据。

## 8. 分阶段落地

### 第一阶段：全员助手接入现有信息员流程

- 所有允许访问的登录用户可以进入课程助手；
- 课程查找、候选确认、纠错、备用线索和手动路径可用；
- 选定结果只带入现有信息员 `LectureForm`，保留原有验证和审核；
- 保留直接打开旧表单的入口，助手失败不阻塞旧流程；
- 记录助手使用和确认证据，但不宣称自动填表准确率。

### 第二阶段：教师/督导模板

- 单独确定教师身份、查看范围、字段、签名/联系方式、审核责任和统计归属；
- 使用相同助手会话和课程证据，但使用独立提交模型或模板；
- 需要单独设计和验收，不把学生字段迁移过去。

### 第三阶段：表达辅助与推广

- 在有真实确认数据后评估语音输入、评价整理和更多角色；
- 任何生成的评价文字必须可编辑、需用户确认，不补写未观察到的事实。

## 9. 验收与观测

### 功能验收

- 信息员可以从日期和教室/教师找到候选并带入基础字段；
- 单例和多候选均显示“都不是”；
- 修改日期/教室后旧候选不会残留；
- 备用来源有明确标签且必须确认；
- 地点/节次冲突不会被静默覆盖；
- 手动路径可完成，表单提交前服务端重新校验；
- 未登录、无权限用户无法调用候选和草稿接口；
- 旧表单直接填写、草稿、版本更新、重复提交和审核测试保持通过。

### 观测指标

记录候选展示数、用户拒绝数、备用查询数、手动覆盖数、最终确认数、放弃点和重复提交情况。把“候选召回”与“用户最终选对”分开；后者需要真实用户确认日志，不能由历史最终表单反推。

### 测试范围

- 服务层：日期/地点/节次/班级规范化、候选去重、来源权限、冲突状态；
- Flask API：登录、角色、用户隔离、当前批次重查、备用来源显式触发；
- 表单回归：草稿、版本、绑定、重复提交和旧入口；
- 浏览器：桌面、320px 移动宽度、键盘操作、读屏标签、都不是、备用来源和手动路径；
- 数据边界：无课表、无候选、多候选、重复业务身份、多场地、多节次和课表批次切换。

## 10. 当前批准范围

本次批准只覆盖：

1. 全员可使用听课助手；
2. 第一阶段接入现有信息员流程；
3. 教师/督导模板独立设计；
4. 不伪造学生字段，不自动认定课程，不把备用来源当成权威来源。

语音、AI 评价生成、教师角色的具体字段和正式上线批次属于后续设计，不在本设计文档中默认批准。
