# 本地调试启动器界面与端口修订设计

## 背景

现有 `本地调试.cmd` 能管理独立调试数据库和 Flask 服务，但双击进入菜单后出现了两个体验问题：

- CMD 会回显内部的 `if`、`powershell.exe` 和 `exit /b` 命令，菜单内容被实现细节淹没。
- 默认端口 `5000` 已被本机另一个 Flask 进程占用。启动器正确地没有终止该进程，但 PowerShell 使用 `Write-Error` 输出了完整错误堆栈，提示冗长且不友好。

现场确认 `127.0.0.1:5000` 的监听进程不属于本启动器。修订不得终止、重启或改动该外部进程。

## 目标

- 将本项目本地调试服务的默认端口固定为 `5087`。
- 双击 `本地调试.cmd` 后只显示简洁中文菜单，不回显内部命令。
- 菜单始终展示服务状态和固定访问地址，无需单独执行“查看状态”。
- 将可预期错误压缩为一行中文提示，不显示 PowerShell 堆栈。
- Flask 服务在后台运行，运行日志继续写入现有独立调试日志文件。
- 保留现有独立调试数据库、固定测试账号、PID 精确管理和命令行操作能力。

## 非目标

- 不修改业务页面、登录逻辑、角色权限或生产启动方式。
- 不读取或修改默认业务数据库。
- 不自动扫描或漂移到其他端口。
- 不终止占用 `5000`、`5087` 或其他端口的外部进程。
- 不增加安装依赖、图形化桌面程序或常驻托盘程序。

## 方案选择

采用“极薄 CMD 入口 + PowerShell 交互与管理器”方案。

`本地调试.cmd` 仅负责定位仓库并调用 `tools/local_debug.ps1`。文件使用无 BOM 的 ASCII 内容和 CRLF 换行，不再包含中文菜单、输入循环或多段操作分发。PowerShell 负责 Unicode 文案、菜单循环、状态查询、操作调用和错误展示。

未采用以下方案：

- 继续在 CMD 中维护中文菜单：改动较少，但仍依赖代码页、BOM 和批处理解析行为。
- 仅提供 `.ps1` 入口：实现更直接，但双击体验和执行策略提示不如 CMD 包装入口稳定。

## 用户界面

双击启动器时显示：

```text
SWU TIC 本地调试
状态：未运行
地址：http://127.0.0.1:5087

1  启动
2  关闭
3  重启
4  打开网页
0  退出

请选择：
```

界面不使用大面积边框、ASCII 图案、蓝紫色配色或多余说明。服务状态在每次回到菜单时重新计算，显示为“运行中”“未运行”或“状态异常”。

菜单操作：

- `1`：准备独立调试数据库和账号，启动服务，健康检查通过后打开网页。
- `2`：只关闭 PID 状态文件记录的本启动器进程树。
- `3`：关闭已记录服务后重新启动。
- `4`：服务可访问时打开网页；服务未运行时只提示，不隐式启动。
- `0`：关闭菜单窗口，不停止已经运行的服务。
- 其他输入：显示一行“请输入 0–4”，等待确认后返回菜单。

每次操作结束后最多显示一条主要结果，并等待用户按回车返回菜单。例如：

```text
[成功] 服务已启动：http://127.0.0.1:5087
[提示] 服务尚未启动
[失败] 端口 5087 已被 python.exe（PID 1234）占用
```

## 组件职责

### `本地调试.cmd`

- 切换到文件自身所在目录。
- 无参数时调用 PowerShell 的 `menu` 动作。
- 有参数时将 `start`、`stop`、`restart`、`status` 或 `open` 传给 PowerShell。
- 原样返回 PowerShell 退出码。
- 文件内容只使用 ASCII 字符，首字节必须是 `@`，不得包含 UTF-8 BOM。

### `tools/local_debug.ps1`

- 新增 `menu` 动作并集中渲染中文菜单。
- 默认端口从 `5000` 改为 `5087`。
- 保留显式 `LOCAL_DEBUG_PORT` 覆盖能力，供自动化验收使用；普通双击和正常命令行使用固定默认端口 `5087`，不会自动换端口。
- 菜单顶部复用状态检查结果，不输出原有多行诊断信息。
- `status` 命令仍保留完整 PID、进程、端口、HTTP 和网址信息，供自动化或人工诊断使用。
- 后台启动 Flask，不显示第二个 CMD 日志窗口；日志继续写入 `data/storage/debug/logs/local-debug.log`。
- 预期失败使用简洁的普通输出并返回非零退出码，不调用会展开调用栈的 `Write-Error`。
- 端口冲突时尽量读取监听进程的名称与 PID；无法读取时只显示端口占用，不影响安全拒绝逻辑。

### 其他组件

`tools/prepare_local_debug.py`、`tools/local_debug_server.py`、独立调试数据库路径和三个测试账号保持现有行为。除非后台启动所需的标准输出重定向需要最小调整，否则不修改这些文件。

## 运行流程

1. 用户双击 `本地调试.cmd`。
2. CMD 静默启动 `local_debug.ps1 -Action menu`。
3. PowerShell 查询 PID、进程和 HTTP 状态并绘制菜单。
4. 用户选择操作，PowerShell 执行对应管理函数。
5. 启动时使用 `127.0.0.1:5087`，创建或更新独立调试数据库，后台运行 Flask 并轮询健康状态。
6. 操作结束后显示一行结果；用户按回车后刷新菜单状态。
7. 退出菜单不影响后台服务，后续可再次双击并选择关闭。

## 错误处理

以下为可预期错误，使用简洁中文提示并返回非零退出码：

- `5087` 被其他进程占用。
- 未找到具备项目依赖的 Python。
- 独立调试数据库准备失败。
- Flask 在限定时间内未通过健康检查。
- 已记录进程无法关闭或关闭后端口仍未释放。
- 服务未运行时请求打开网页。

错误提示不得包含 PowerShell 的 `CategoryInfo`、`FullyQualifiedErrorId`、脚本行号或调用栈。详细的 Flask 运行信息保留在独立日志文件中。未知异常显示精简消息和日志路径，不吞掉非零退出码。

## 兼容性

- 支持 Windows PowerShell 5.1 和当前 Windows Terminal/CMD 双击入口。
- 保留以下非交互调用：

```text
本地调试.cmd start
本地调试.cmd stop
本地调试.cmd restart
本地调试.cmd status
本地调试.cmd open
```

- 默认网址变更为 `http://127.0.0.1:5087`。
- 已存在的调试数据库、上传目录和日志继续复用，不做清空或迁移。

## 测试与验收

实施采用回归测试先行：

1. 验证 `本地调试.cmd` 首字节为 `@`、无 UTF-8 BOM、使用 CRLF，且将交互委托给 PowerShell。
2. 验证 PowerShell 暴露 `menu` 动作，默认端口为 `5087`，显式端口覆盖仍经过范围校验。
3. 在端口被外部进程占用的测试中，验证启动失败、外部进程仍存活、输出不含 PowerShell 堆栈字段。
4. 验证菜单状态、选项及无效输入提示契约。
5. 在 `5087` 空闲时执行真实 `start`、重复 `start`、`status`、`restart`、`open` 和 `stop` 验收。
6. 验证服务后台运行时没有额外可见 CMD 窗口，网页返回成功响应，日志持续写入独立日志文件。
7. 验证独立调试数据库中的 `super`、`manager`、`user001` 仍可使用密码 `1234564` 登录。
8. 运行完整测试套件、Python 编译检查和 PowerShell 语法解析。
9. 验证默认业务数据库未创建或未变化，`5000` 端口原有外部进程仍存活。

## 验收标准

- 双击窗口不再回显 `if`、`powershell.exe`、`exit /b` 等内部命令。
- 菜单与操作反馈符合本设计中的精简文案和选项。
- 普通启动始终使用 `5087`，不会自动选择其他端口。
- 预期错误只显示简洁信息，无 PowerShell 红色堆栈。
- 启动、重启、打开网页和关闭流程可用，且只管理本启动器记录的进程。
- 独立调试数据库与测试账号行为保持不变。
- 完整自动化测试通过，仓库中不出现数据库、PID 或日志运行产物。
