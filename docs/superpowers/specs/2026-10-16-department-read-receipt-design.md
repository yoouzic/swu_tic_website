# 部长个人已阅标记

用户确认：部长打开表单详情后自动标为已阅；小组长通过后仍显示“部门已审核”。

- 审核状态、审核权限、审核人、意见、评分和版本链维持现有含义。
- 有“审表_部门”权限的账号，在本人可审核范围内的“部门已审核”表单旁看到“我未阅／我已阅”。部长自己审核的版本直接显示“我已阅”。其他账号的查看互不影响。
- 列表、原始详情 GET 和导出不写已阅记录。网页成功展示详情后，使用带 CSRF 保护的 POST 记录当前账号实际打开的物理版本及 updated_at。详情弹窗、桌面预览、独立详情页、审核页面都接入。
- 独立表存储个人记录，不触碰 LectureForm.updated_at；新版本或内容更新时间变更后，对其他查看者重新显示未阅。不推测上线前是否看过。
- 只允许本部门、非本人、有效成员、当前最新且仍为部门已审核的表单；记录接口拒绝过期版本及伪造的版本时间。历史版本不展示个人标记，也不触发已阅请求。
- 记录失败时保持未阅，展示可重试的提示；只有服务端成功后才改变标记。

采用独立个人记录而非新增审核状态，因为用户明确保留现有审核流程；不采用浏览器本地记录，因为更换设备后仍需保留。

验证：隔离 SQLite 测试权限、幂等、版本隔离、状态及评分不变；JavaScript 测试成功展示后写入、失败提示及列表更新；实际浏览器检查桌面和手机布局。

上线需要在目标数据库创建新增表，不能用本地测试结果声称线上已生效。
