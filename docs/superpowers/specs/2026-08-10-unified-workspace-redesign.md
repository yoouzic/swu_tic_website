# 西大听课工作台统一架构与交互重设计

日期：2026-08-10

## 1. 项目背景

当前系统使用 Flask、Jinja2、Bootstrap、jQuery 和少量原生 JavaScript。功能覆盖信息员填表和听课登记、管理员审核与部门管理、超级管理员的全局配置、导入导出和统计。

代码与页面已经具备完整业务能力，但用户体验存在明显结构性问题：

- `base.html` 会给绝大多数内部链接动态添加 `target="_blank"`，导致一次普通操作产生多个浏览器标签页。
- 信息员、管理员和超级管理员分别拥有独立首页，其中管理员角色还要从角色首页再次进入仪表板，形成重复入口。
- 多个首页和仪表板自行声明完整 HTML、导航栏、内联样式和脚本，没有共享应用壳层。
- `app/static/css/style.css` 几乎为空，视觉规则散落在模板内部，颜色、圆角、间距和状态反馈不一致。
- 首页使用大量等权快捷卡片和高饱和渐变，重要任务、统计信息和低频入口缺少清晰优先级。
- 管理员审核、成员管理和统计查看经常在列表、详情和编辑页之间往返，返回后容易丢失筛选和滚动上下文。
- `app/blueprints/admin.py` 同时承载多个业务域，体积很大。本次不做全面后端拆分，只抽离与统一工作台和导航直接相关的表示层逻辑。

仓库中的 `SWU_TIC-submit` 是带 Git 历史的规范实现目录。`SWU_TIC-main` 包含本地运行数据、虚拟环境和验收截图，源代码内容与提交目录基本一致。本次设计和实现以 `SWU_TIC-submit` 为准，运行验收可以复用 `SWU_TIC-main` 的本地 Python 环境和测试数据，但不能把运行数据提交进仓库。

## 2. 目标与非目标

### 2.1 目标

- 为三种角色建立同一套应用壳层和操作语言。
- 取消内部链接自动新开标签页，减少不必要的页面往返。
- 登录后直接进入统一工作台，用真实待办、继续处理和快捷发起代替重复首页。
- 将信息员的填表、预约和记录，管理员的审核和成员管理，超级管理员的设置和统计分别收拢为业务中心。
- 通过统一设计令牌、组件和状态规范改善视觉层级、可读性和移动端体验。
- 保留现有路由、表单字段名和核心业务语义，控制回归风险。

### 2.2 非目标

- 不把服务端渲染系统重写为 React、Vue 或单页应用。
- 不全面拆分 `admin.py` 的全部业务域。
- 不重做数据库模型、权限模型或自动审核算法。
- 不以安全加固为本轮主要目标，也不主动削弱已有权限校验。
- 不在任务型后台页面加入装饰性插图、照片、玻璃效果或复杂动画。

## 3. 已确认的设计方向

### 3.1 信息架构

采用“统一工作台”方案：

- 桌面端使用固定侧栏。
- 顶部栏承载面包屑、全局搜索入口和当前用户区。
- 首页只承担工作分发，不再重复介绍系统功能。
- 详情优先在当前上下文内使用抽屉或模态框。
- 长表单、完整审核、统计分析和系统设置继续使用独立页面，但始终位于统一壳层内。

### 3.2 视觉读取

这是面向校内信息员、管理员和超级管理员的内部业务系统重设计。界面需要可信、克制、清晰，采用现有 Bootstrap 5.3 加自定义语义化设计令牌，不伪装成其他官方设计系统。

设计参数：

- `DESIGN_VARIANCE: 4`，布局适度不对称，避免等权卡片堆叠。
- `MOTION_INTENSITY: 3`，动效只用于反馈和状态切换。
- `VISUAL_DENSITY: 7`，满足日常管理效率，同时保留可读间距。

### 3.3 色彩与材质

采用已确认的“墨黑朱红”方向，禁止蓝色、紫色和蓝紫渐变作为整体视觉语言。

核心设计令牌：

```css
--color-nav: #292d2b;
--color-accent: #9b493c;
--color-accent-strong: #78362e;
--color-background: #f5f3f1;
--color-surface: #fffefd;
--color-text: #231f1d;
--color-text-muted: #746b66;
--color-border: #e2dcd7;
--color-accent-soft: #f3e8e5;
```

朱红只承担主操作、活动导航和焦点强调。成功、警告和错误可以使用语义色，但不得抢占主操作视觉层级。页面保持单一浅色主题，本轮不增加深色模式。

### 3.4 排版、形状与动效

- 字体使用本地系统中文无衬线栈：`-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`PingFang SC`、`Microsoft YaHei`、`sans-serif`。
- 控件圆角统一为 8px，内容容器为 10px，大型对话框为 12px，按钮文字不得换行。
- 卡片只用于表达真实分组，不把每个数字和入口都装进独立卡片。
- 数字使用等宽数字特性，统计指标通过排版和分隔线形成层级。
- 交互过渡控制在 120ms 至 180ms，只动画 `transform` 和 `opacity`。
- 所有动效尊重 `prefers-reduced-motion`。
- 不使用渐变背景、外发光、玻璃效果、装饰性状态点和大面积阴影。

## 4. 应用架构

### 4.1 保持的技术边界

继续使用 Flask 路由、Jinja 模板、Bootstrap 5.3、Bootstrap Icons、jQuery 和原生 JavaScript。现有业务 API 和服务端页面继续工作，不引入前端构建链和新的大型依赖。

### 4.2 新增表示层模块

建议新增以下结构：

```text
app/
  ui/
    __init__.py
    navigation.py       角色和权限驱动的导航定义
    workspace.py        统一工作台的数据组装
  templates/
    base.html           唯一应用壳层
    partials/
      _sidebar.html
      _topbar.html
      _flash_messages.html
      _page_header.html
      _empty_state.html
      _confirm_dialog.html
    main/
      workspace.html    三种角色共用的工作台模板
  static/
    css/style.css       设计令牌和共享组件样式
    js/app-shell.js     侧栏、抽屉、移动端菜单和活动导航
```

`navigation.py` 提供导航组定义和 `build_navigation(user, endpoint)`。每个导航项包含标签、端点、图标类、允许角色和可选权限要求。模板只接收已经过滤的导航数据，不重复编写角色判断。

`workspace.py` 提供 `build_workspace(user)`，返回角色中立的视图模型：

```python
{
    "title": "上午好，林老师",
    "summary": "先处理 7 份待审核表单，再查看本周补交情况。",
    "metrics": [],
    "tasks": [],
    "quick_actions": [],
}
```

工作台模板只负责展示，不直接编写复杂查询。

### 4.3 请求与渲染流程

```text
请求
  -> 现有会话和用户加载
  -> 导航构建器按角色与权限过滤菜单
  -> 工作台构建器组装指标、待办和快捷操作
  -> Jinja 渲染统一壳层与业务内容
  -> 页面内抽屉或模态框调用现有 JSON/HTML 端点加载详情
```

`main.index` 成为唯一登录后工作台入口。现有 `admin_dashboard` 和 `super_admin_dashboard` 路由保留，并重定向到 `main.index`，防止已有书签失效。未登录用户继续看到公共入口和登录页。

## 5. 导航与角色差异

统一导航分组：

1. 工作
   - 今日工作
   - 听课与填报
   - 表单审核
2. 管理
   - 人员与部门
   - 课程与登记
   - 统计与导出
   - 系统设置

角色可见性：

| 模块 | 信息员 | 管理员 | 超级管理员 |
| --- | --- | --- | --- |
| 今日工作 | 可见 | 可见 | 可见 |
| 听课与填报 | 可见 | 可见 | 可见 |
| 表单审核 | 不可见 | 按权限可见 | 可见 |
| 人员与部门 | 不可见 | 按权限可见 | 可见 |
| 课程与登记 | 个人登记 | 部门范围 | 全局范围 |
| 统计与导出 | 个人记录 | 按权限可见 | 可见 |
| 系统设置 | 不可见 | 不可见 | 可见 |

移动端侧栏收进顶部菜单。活动导航必须根据当前端点自动高亮，不能依赖每个模板手工添加 `active`。

## 6. 三类角色的操作流

### 6.1 信息员

1. 从“今日工作”直接继续最近草稿、开始今日听课或处理补交提醒。
2. “听课与填报”业务中心使用同页标签组织可登记课程、我的预约和我的表单。
3. 查看课程、预约或表单详情时使用当前页面抽屉，不打开新标签页。
4. 完整听课表单继续使用独立页面，并增加固定分区导航、课程信息自动填充、持续保存状态和底部主操作区。
5. 提交成功后在当前上下文显示结果、记录入口和下一步建议，不跳到孤立的成功页。

### 6.2 管理员

1. “今日工作”按优先级展示待审核数量、异常表单和部门补交人员。
2. 审核中心采用列表与预览并列布局。筛选列表保留在左侧，右侧展示表单摘要、规则检查和主要操作。
3. 完整审核进入独立页面，顶部固定主要操作、草稿状态和返回队列入口。
4. 提交、驳回或暂存后回到原队列位置，保留筛选条件，并自动选中下一份可处理表单。
5. 部门和成员管理采用主从布局：部门结构、成员列表和编辑抽屉处于同一页面。

### 6.3 超级管理员

超级管理员继承管理员流程，并增加：

1. 工作台集中展示自动审核任务、导入失败、待补交和数据异常。
2. 人员与部门中心支持跨部门结构和成员移动，编辑操作在抽屉内完成。
3. 系统设置中心使用同页标签组织教学周期、考核豁免、自动审核和导入工具。
4. 统计与导出共享同一组筛选条件，查看结果、保存快照和导出不重复配置。

## 7. 页面与组件规则

### 7.1 页面标题区

每个页面只保留一个主标题、一个简短说明和最多一个主要操作。次要操作进入更多菜单或页面内容区，避免重复 CTA。

### 7.2 指标区

工作台指标使用一行数字排版和稀疏分隔线，不使用四个高饱和渐变卡片。指标必须与当前角色的可操作任务相关。

### 7.3 筛选与列表

- 筛选条件在桌面端保持一行或两行，移动端折叠为筛选抽屉。
- 当前筛选写入 URL 查询参数，刷新或返回页面后仍可恢复。
- 表格只展示决策所需列，低频列进入详情抽屉。
- 行操作不得只在鼠标悬停时出现。
- 批量操作只在存在选中项时显示，并明确选中数量。

### 7.4 表单

- 标签始终位于输入框上方，不能用占位符代替标签。
- 帮助文字位于输入框下方，字段错误紧邻字段显示。
- 长表单使用固定分区导航和明确保存状态，不拆成强制逐步向导。
- 主操作在桌面端位于页面标题区或底部操作区，移动端固定在底部。
- 提交、驳回、删除和覆盖导入使用统一确认对话框。

### 7.5 抽屉与模态框

- 简单查看和轻量编辑使用右侧抽屉。
- 需要用户明确确认的短操作使用模态框。
- 超过一个屏幕的复杂内容不得塞进模态框，应进入独立页面。
- 移动端抽屉转为全屏，必须提供清晰返回入口。

## 8. 加载、空、错误和成功状态

- 加载状态使用与最终内容相同结构的骨架，不使用全屏旋转加载器。
- 空状态说明为什么为空，并提供一个明确的下一步操作。
- 字段错误显示在字段下方。
- 页面区域加载失败时，在对应区域提供错误说明和重试按钮。
- 网络中断、自动保存失败和后台任务失败必须持续可见，不能只使用短暂 toast。
- 自动保存状态至少包含“正在保存”“已保存”“保存失败”三种状态。
- 批量任务显示已处理数量、总数、失败项和可恢复入口。
- 成功反馈保留在当前上下文，并提供查看结果或继续下一项的入口。

## 9. 响应式与可访问性

### 9.1 响应式

- 1440px 及以上：固定侧栏，内容最大宽度受控，列表与详情可以并列。
- 1024px：侧栏可折叠，双栏布局保留但缩小次要区。
- 768px：业务内容转为单主列，筛选和详情使用抽屉。
- 390px：顶部菜单，抽屉全屏，主要操作固定在底部，表格转换为重点字段列表或允许受控横向滚动。

### 9.2 可访问性

- 主按钮、文字、输入框、占位符、帮助文字和焦点环满足 WCAG AA 对比度。
- 所有交互元素具备键盘焦点状态。
- 导航折叠、抽屉和模态框提供正确的可访问名称和关闭行为。
- 图标必须来自现有 Bootstrap Icons，不绘制自定义 SVG 图标，也不混用其他图标族。
- 核心操作不能依赖颜色或鼠标悬停才能识别。

## 10. 实施边界

高频页面进行布局和操作重构：

- 公共入口和登录页。
- 统一工作台。
- 信息员听课表、听课登记、我的表单和个人资料。
- 管理员审核队列、完整审核、表单查看、人员与部门管理和统计。
- 超级管理员系统设置、课程管理、导入导出、自动审核和考核配置。

其他低频完整页面至少接入统一壳层、设计令牌、活动导航和统一消息状态。本轮不删除现有端点，不改变数据库字段，不替换自动审核实现。

## 11. 测试与验收

### 11.1 自动化测试

新增模板和路由契约测试：

- 所有完整业务页面继承统一壳层或使用明确的公共页布局。
- `base.html` 和各独立模板不再包含自动添加 `target="_blank"` 的脚本。
- 三种角色获得正确的导航分组和工作台内容。
- 旧管理员仪表板路由正确重定向到统一工作台。
- 核心表单字段名、请求方法和现有业务端点保持兼容。
- 新增 UI 构建函数有角色、权限和空数据覆盖。

全部现有单元测试继续通过，并运行 Python 编译检查。

### 11.2 浏览器验收

分别使用信息员、管理员和超级管理员账号验证：

- 登录后一次进入统一工作台。
- 内部导航在当前标签页完成。
- 信息员可以继续草稿、登记、查看预约和提交表单。
- 管理员可以筛选审核队列、查看预览、完成审核并继续下一份。
- 管理员可以在部门、成员列表和编辑抽屉之间保持上下文。
- 超级管理员可以进入设置、导入、自动审核和统计业务中心。
- 页面在 1440、1024、768 和 390 像素宽度下可用。
- 加载、空、错误、保存、成功和批量任务状态均有可见反馈。

### 11.3 可量化完成条件

- 自动给内部链接添加新标签页的脚本数量为 0。
- 登录后角色首页与管理仪表板的重复跳转层级从 2 层降为 1 层。
- 高频任务从工作台最多一次导航即可开始。
- 全部完整业务页面使用统一壳层或明确的公共页布局。
- 新增测试、现有测试、Python 编译检查和浏览器核心流程验收全部通过。

## 12. 设计决策总结

本次采用渐进式重构：统一壳层、统一工作台和业务中心先解决操作跳转与布局混乱，再在不改变核心业务语义的前提下重排高频页面。视觉上使用墨黑朱红、单一浅色主题和高信息密度排版。生成式图片不用于任务型后台页面，因为它不会提高操作效率；公共入口和登录页也优先使用真实系统身份、排版和现有品牌资产，保持离线与本地部署一致性。
