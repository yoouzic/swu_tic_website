# 填表助手补全 Implementation Plan

**Goal:** 课程确认后用异常、推荐两问补齐可由用户确认的字段，并突出剩余必填项。

**Architecture:** 保留现有匹配接口及确认复验。新增独立前端模块处理两问、标准字段写入、动态待填清单；通过课程确认事件激活。草稿继续只保存标准表单字段。

**Tech Stack:** Flask/Jinja、原生 JavaScript、Node test、Playwright CLI。

- [x] 补充失败用例：无异常填三项无；推荐勾三方法并填四项非常好；改回答还原助手写入但保留人工编辑；反馈不足50字及无效电话仍待完成。
- [x] 实现 form-completion-assistant.js，保留课程反馈与签名由本人填写。
- [x] 在 lecture_form.html 加两问与动态清单，把完成操作按钮放进同一 flex 容器。将可见名称改为填表助手。
- [x] 接入课程确认及草稿恢复事件，更新字段时走已有 change/input 草稿机制。浅色强调与文字提示同时提供，点击清单聚焦字段。
- [x] 运行相关 Node/Python 测试，重启隔离服务，用浏览器验证推荐/不推荐、有/无异常、人工修改、草稿恢复、桌面并排及移动无溢出。

交互决定沿用用户本次授权：异常问覆盖变化、异常、不足建议；推荐选项明示三个方法与四项非常好。推荐条件由用户明确确认，不推断实际课堂质量。不推荐时只填不推荐，其余保留本人选择。所有自动写入可以继续编辑；更改回答时只还原仍等于助手值的字段。
