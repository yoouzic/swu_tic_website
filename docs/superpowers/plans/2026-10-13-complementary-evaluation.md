# 补集评价交互实现计划

用户明确选择：先在助手里勾选实际教学方法，再做补集评价。

## 已确认设计

- 保留课程变化/异常/建议问题，随后选择实际教学方法（PPT演示法、讲授法、师生互动法，可多选）。不默认勾选教学方法。
- 询问哪些环节没有达到“非常好”：管理课堂纪律、调动课堂气氛、课件制作质量、整体教学效果，多选。
- 用户确认选择后，未选的适用项目才写“非常好”；选中项目逐项回答现有表单支持的“好”或“一般”。未使用 PPT 时课件质量为“无”，不列入补集评价。
- 推荐课程作为独立问题，评价不影响推荐；可以返回修改或跳过助手，仍可在原表填写。
- 从已有草稿恢复时保留人工评价和教学方法；切换照片记录不沿用上一条的默认值，返回问题不直接改写表单。
- 沿用现有字段和持久化方式，不新增数据库表。助手的课表开放条件保持现状。

## 实施与验证

1. 先补方法选择、补集批量填写、推荐独立、课件适用性和记录切换的失败测试。
2. 扩展当前助手的问题状态和控件，使用原表单字段作为保存数据。
3. 验证部分选择、多项选择、全部非常好、跳过/返回、草稿恢复和手工修改。
4. 在隔离浏览器环境验证完整问答和移动布局；更新脚本缓存参数。
5. 发布同一代码到测试站和正式站，备份现有数据，核验两站的独立配置与数据库。

## 本地验证结果

- 45 项 Node 测试通过，包括多选逐项评价、返回不改写、跳过恢复人工值、草稿恢复、新增 PPT 的适用性和照片记录切换。
- 58 项 Python 回归和 7 个子测试通过，包括模板、草稿、提交事务、照片草稿并发和无课表手动填写边界。
- 隔离浏览器实际确认课程后进入补集助手；验证 PPT 多选、两项分别选择一般/好后仍可推荐、刷新恢复，以及无 PPT 时三项全部非常好。
- 390 px 手机布局没有横向溢出，按钮点击有效。测试使用本地独立数据库，没有创建线上测试照片或填写正式业务记录。
