> 后续新增就近分层与最多两次按需澄清，见 [落地验证](SITE_CONTEXT_ADAPTIVE_GUIDANCE.md)。下文是此前自动处理版本的实现与历史指标。

2026-10-02。承接 `SITE_CONTEXT_FUSION.md`，本轮按用户追加的“无感体验”调整：**拍清楚门牌 → 后台自动处理 → 确认课程**。不再默认逐项追问楼栋、门牌和教师；地图与人工框选收进“匹配不对？调整线索”。评价仍由信息员填写，系统不自动提交听课表。

## 本轮实现

- 课程候选默认先展示前三项，保留更多课程、针对性问题和手工纠错。确认课程后，原有服务端复验并回填完整课程、教师、班级、教室、起止节次。
- 提问成本加入选项数量：`cost = 原回答成本 × (1 + (选项数 - 1) / 3)`。20位教师、2栋楼的回归场景优先问楼栋。候选不超过3项时直接看卡片；机器门牌冲突问题仍可在辅助提问路径中出现。
- 定位由负分惩罚改为有界正向支持：`位置贡献 = 位置权重 × 可靠性 × log(1 + 位置匹配值)`。未知地图贡献0；已映射但偏移的楼不再单纯因为有地图而吃负分。未证明绝对公平或位置概率校准。
- 单项答案可修改；改楼栋/门牌时清除旧教师和节次约束，保留独立照片线索。
- 门牌原文在课程卡显示为四位数字，例如“8教 · 门牌0609”。

## 自动门牌区域

`app/services/door_regions.py` 提供有界的本地图像区域提议与透视校正：

1. 整图OCR后，对检测到的短文本区域复核；读成 `O6O9` 也可进入复核，不要求整图已经给出纯数字。
2. 将四边形区域校正为横向文字图，绕过第二次文字检测与方向分类，保留冲突读数。
3. 没有高分数字结果时，从边缘、闭合轮廓、长宽比提出最多4个门牌形状区域，再单行识别。不是训练过的门牌检测器，不保证所有门牌材质/遮挡/反光都适用。
4. 最多复核4个文字区域及4个形状区域，防止无界重试。依然无法识别时提供重拍、手填、手动框选作为备用。

手动框选端点仅接受本人未提交、未归档、未确认课程的记录。只更新机器读数，不修改原图、GPS或人工教室确认；识别失败保留旧证据。客户端抑制切换记录后的晚到响应。

## 地图方案与数据边界

本轮采用“可核对的楼栋数据层 + 本地校园背景 + 人工纠错入口”，不用更精美的底图掩盖楼号数据缺失。

- 从已有OSM原始响应提取1596项道路、建筑、水体、绿地背景几何；紧凑GeoJSON约628 KB，浏览器只请求本机静态文件，无在线瓦片依赖。
- **具有楼号映射的仍只有14栋**。灰色背景建筑不能当作新增的楼号覆盖；没有根据学院名称猜编号。
- 选楼地图已接入现场记录：附近列表、搜索、缩放、拖动、北向和比例尺、定位点与报告精度圆、选中状态。选择后需点击“使用此教学楼”，只写入人工作答，不生成/改写GPS。
- 课表中无坐标的地点继续可搜索。F、G、MC1等原始代码不强行改名为数字教学楼。不同课表快照的缺失数量会不同，页面按当前快照计算。
- 数据统一WGS84，保留OSM署名与ODbL链接。地图社区数据未经过现场核验；跨校区同号完整映射仍未解决。

来源核实（2026-10-02）：

- [学校信息化服务手册](https://nic.swu.edu.cn/__local/E/B7/6F/F0C9CD52E817BC58DF55C8EB3A1_E8E94108_CB2F5A.pdf?e=.pdf)明确列出校园GIS与 `map.swu.edu.cn`。本次HTTPS访问为SSL EOF，HTTP为502，未得到可导入GIS数据。
- [学校2026研考公告](https://yz.swu.edu.cn/info/1005/3451.htm)提供校园地图附件；附件下载要求验证码。本次没有取得附件图像，也没有把它当作已验证坐标来源。
- [youziauth地图文档](https://github.com/yoouzic/youziauth/blob/main/docs/simulation-map-picker.md)可参考选点/坐标转换/模拟方式；不引入登录、打卡或随机定位偏移。

下一阶段数据路线：获取校方可用的楼号/建筑资料 → 与课表地点建立有来源的别名映射 → 在已知楼栋采集多个手机位置 → 独立验证后发布地图版本。若暂时无法取得校方GIS，可用明确人工核验的坐标补点；不能仅靠未配准的校园示意图推算精确经纬度。在线地图可作为可选背景，不能承担楼号真实性或室内定位准确性的保证。
