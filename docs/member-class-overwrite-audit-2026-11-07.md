| --- | --- | --- |

| 普通填表助手 `setBlankField` | 用户确认候选后 | 服务器核验快照，仅填当前空白字段；普通手改会使旧候选请求失效。 |

## 基线缺陷与最小复现

1. **选登记与旧 GET 交错。** 显式 GET 发出时班级为简称；选择同班级的新课程
   不增加编辑版本。旧草稿返回后，可恢复旧全称和旧课程，但保留新登记 ID。
   随后的保存重试会把这份混合内容持久化。初始自动 GET 虽能保护非空班级，
   仍可能覆盖其他刚选好的课程字段。
2. **选登记没有保存。** 草稿原本为已保存状态时，选择登记既不标记 dirty，
   也不触发自动保存；重开后可能恢复旧课程/班级。
3. **重置后初始回填复活。** 编辑或错误页的 100 毫秒定时器尚未执行时 reset，
   基线定时器仍会恢复旧班级、旧课程以及照片元数据。
4. **跨标签版本边界。** 原有数据库 CAS 保护请求内部的并发改写，但不能证明
   后发请求来自最新的浏览器草稿。同账号旧页面可能在新页面保存后再提交旧值。
   两个独立 HTTP 测试客户端已复现旧 PUT 和旧 DELETE 均成功的情况，不能只以
   单页 GET 保护代替。

前两项及第三项已在隔离 Node 重放中触发失败断言；正常手输、清空后重新输入、
无事件改成不同值、原有多 GET/删除保护均通过。复现脚本保存在被 Git 忽略的
`output/2026-11-07-class-input-probes/`。

## 修复口径

- 选择登记会明确作废旧读取、通知助手课程信息已变，并标记草稿需要保存。
- reset 或明确选择新课程时取消旧的初始化回填，避免隐藏的登记/照片信息也混入。
- 页面、普通草稿和现场记录写入统一携带所见草稿版本。服务器保留原有 CAS，
  再检查客户端版本，拒绝顺序到达的旧标签写入。版本在业务字段外传递，不保存进
  表单；计算包含草稿身份、原始内容、微秒更新时间和填写策略，无需数据库迁移。
- GET/成功写入返回 `draft_revision`；写请求发送
  `X-Lecture-Draft-Revision` 或外层 `expected_draft_revision`。缺版本返回 428，
  版本失配返回 409；均不修改数据。新建表单消费草稿也检查隐藏版本，已有表单编辑
  继续使用自己的表单版本校验，不受另一张新建草稿影响。
- 拍照、改教室、确认课程、恢复照片逐步传递新版本，不能只在整串操作最后更新。
  单页保存继续输入时，会接收自己的成功版本后再保存更新的内容；旧上下文响应
  不能升级新上下文版本。真正的版本冲突停止自动重放并保留页面输入。
- reset 等待本页未完成的保存后仅删除一次。DELETE 使用原子版本谓词，避免校验后
  又删掉其他页的新写入。
- 已经成功的完全相同提交仍可按原有 120 秒回执只读返回首次结果，不重新创建表单、
  不消费后来产生的新草稿。不同内容不能用这个例外绕过版本校验。
- 如果 A 页面尚未提交、B 页面已切换或更新了共享草稿，A 的旧提交将返回冲突；
  不再从 A 的过期页面绑定或消费 B 的记录。已有表单编辑和已接受请求的精确重试
  分别保留原有独立版本检查与幂等行为。
- 有效表单提交前先等待本页未完成的自动保存，使用该次保存返回的新版本再提交，
  防止自己的 PUT 先完成、随后 POST 却携带旧版本而错误冲突。

统一 `none` 版本只描述当前没有草稿，不记录“曾创建又删除”的历史代次。它可以
阻止覆盖现存的新草稿，但不是持久化删除标记；旧空页在再次无草稿时仍可能新建
独立草稿。未据此宣称覆盖所有跨设备历史状态。

旧页面缺少版本时会安全拒绝写入。升级后应保留尚未提交的文字并重新打开填写页；
不能以自动获取当前版本后重试旧内容的方式绕过冲突。
