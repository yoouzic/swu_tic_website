# 专业年级以课表班级为准（2026-11-08）

## 口径修正

用户确认目标是与对应课程的课表班级对齐，不是优先保留简称。此前把“没有自动
扩写简称”作为验证结论，不能代替这一完整目标。

权威来源是课表的“教学班组成／班级组成”，不是旁边的“专业组成”。课表用简称
就采用该简称，课表本身用全称就采用该全称；合班保留该记录的完整班级组合。
年级、班号、分隔符可以按已有规则整理，但不根据专业名称推断新的班级名称。
没有匹配或尚未确认课程时，不凭猜测改写输入。

## 实际来源核对

只读检查线上当前选中课表批次的 18,208 条助手索引，逐行比较索引班级与原始
班级字段。按现行格式规则规范化后，名称差异为 0。

“机制”“农林经济”出现在相应原始班级字段中，因此那几条课采用这些文字是
因为课表如此记录，不是因为系统应该偏好短名称。该结论不推广到其他课表行。

新增数据库来源测试覆盖五种情况：课表机制简称／专业全称、课表机械全称／专业
简称、课表农林经济简称／管理专业、课表管理全称／农林专业，以及多个合班。
通过实际导入索引、服务查询、候选展示和确认快照验证班级取自课表，候选身份不变。

## 发现与修复

普通填表助手原先只补空白字段。即使用户明确确认了课程，已填的专业年级仍会
被保留，可能与已选课表行不同。页面提示也写着“已填写的内容会保留”。

现在仅在该课程的确认请求成功、且请求仍对应当前页面状态时，将专业年级采用
服务器重新核验后返回的课表班级。其他非空手填字段仍按原有行为保留。确认提示
提前说明这一点；成功后仍提示核对回填信息。

迟到响应、请求期间的手改和草稿版本保护继续生效。没有班级证据时不擦除输入；
此次也未改变既有人工覆盖 API、无匹配时的手动填写或历史表单数据。
确认请求还记录班级输入节点和当时的值：即使浏览器改值没有发出 `input` 事件，
响应到达时发现变化也会保留新输入并要求重新核对，防止此次对齐引入新的覆盖。

客户端脚本版本更新为 `20261108-class-alignment-v1`。
