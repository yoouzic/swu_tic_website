# 填表助手跳过授课教师后查不到课程（2026-11-23）

## 反馈与结论

用户反馈：填表助手中跳过填写“授课教师”后查不出课程，其他信息没有缺失，
连续查询两次结果相同。

定位结论：这不是课表或查询失败。服务端已经检索到候选课程（响应中
`candidates` 可达 20 条），但助手在“无法继续区分”或“问题预算用尽”时把状态
切到 `manual`，前端在该状态不渲染任何课程卡片，于是用户看到“暂无法确定课程，
请补充信息或手动填写”或“已保留确认过的信息”，感觉像是查不到课程。

## 触发条件

- 用户已知日期、教室、节次（以及可选的班级），唯独不知道授课教师。
- 这些条件命中的课程超过 3 门，教师是唯一还能继续缩小的维度。
- 助手问“你记得授课教师吗？”时点击“我不知道，跳过此题”。

此时 `_select_kind()` 已没有可问的事实维度（其余事实已知、教师已问过），
原实现直接返回 `stage='manual'`；候选仍随响应返回，但前端只有候选问题
（`candidate`）和确认页（`confirm`）会渲染课程卡片，`manual` 页只有一句提示。

真实课表（2026-2027-1，18208 行）中按“星期+教室+节次+班级”聚类，同组超过
3 门课的有 381 组、2257 行。典型例子：2026-10-29 第四运动场第 7-8 节有 47 门
体育课（响应截断为 20 条），且这些课的班级字段只有“2025”，跳过教师后无法
再靠班级区分。

## 修复

服务端 `app/services/listening_assistant_guide.py`：

- `_render()`：候选课程超过 3 门且问题预算用尽，或已没有可问的区分维度时，
  返回 `stage='candidate'` 并展示候选课程，不再落入 `manual`。
- `_candidate_question()`：候选问题按每页 3 门分页（`option_batches`），只包含
  客户端实际收到的候选（最多 20 条）。
- `_candidate_display_order()`：候选展示时把“与已填条件无冲突”的课程排在前面，
  避免同一教室不同节次的课程占满前 20 条。
- `_answer_candidate()`：接受分页候选用候选 ID 作答（`custom_value`），并让
  选中的课程排在返回列表首位，保证后续“确认”页面能取到它。

前端 `app/static/js/listening-assistant.js`：

- 候选阶段启用“换一批（n/m）”分页；分页选择发送候选 ID 而不是第一页的 A/B/C。
- 候选阶段的“D. 都不是，手动填写”统一进入手动填写，不再误开自定义输入。
- 脚本版本号更新为 `20261123-course-paging-v1`。

## 验证

- Python 新增 5 条回归：跳过唯一可区分教师后仍展示并可选候选、问题预算用尽
  仍展示候选、分页只覆盖已下发候选、与已填条件无冲突的课程优先、伪造候选 ID
  被拒绝。填表助手相关 Python 集合 207 passed、63 subtests passed。
- Node 新增 1 条回归：分页候选项发送候选 ID。脚本集合 33 passed。
- 隔离实页（真实课表副本，`user001`）：
  - 表单除教师外全部填写 → 核对课程 → 跳过教师：出现“请选择本次听课课程”，
    第一页就是与所填节次一致的课程，有“换一批（1/7）”，不再进入手动状态。
  - 翻到第二页选中课程 → 确认页显示课程/教师/教室/节次/班级/日期 →
    确认后教师等字段回填，状态“已完成”。
  - 空表单按“日期 → 跳过教师 → 教室 → 节次”回答到底：问题预算用尽后同样
    展示候选并进入确认页。
- 全量 `pytest tests -q`：2178 passed、1280 subtests passed。另有
  `test_course_clear_identity_reuse`（2 条）、`test_course_page_header_migration`、
  `test_unified_shell` 共 4 条失败；在干净 HEAD worktree 上复跑同样失败，
  属于既有失败，与本次改动无关。

## 边界

- 候选仍受既有 20 条上限约束；极端聚集课程（如 47 门体育课）中，超出前 20 条
  的课程仍需手动填写。后续若要彻底覆盖，需要在候选契约层扩大上限或增加
  课程名称维度的追问。
- 跳过 2–3 门课的候选卡片仍按原设计进入手动填写（用户已看到候选后主动放弃）。
